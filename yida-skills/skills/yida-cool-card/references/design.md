# 原生酷卡片的默认设计与数据契约

用于用户要求设计、重做或美化宜搭原生酷卡片。视觉质量不是节点数量；先确定接收者看完需要知道什么、下一步做什么，再选原生模板和组件。CLI 创建和读取、官方编辑器保存的能力边界仍见 SKILL.md。

## 模板作为起点

先检查 `cool-card templates APP --type im|onebox`，再按需查看官方编辑器的预设模板。两处目录不保证相同：应用管理目录返回的业务模板，不等于编辑器全部预设模板。查询不实例化；使用模板会替换当前编辑内容，只在目标新卡片或已备份且允许替换的卡片上进行。

优先选择信息形态匹配的模板：任务处理用工单/成果确认，业务简报用项目进度/营收，活动用订餐/投票，入口介绍用应用介绍。复用结构、原生组件与语义样式，替换模板中的品牌、日期、示例数据、链接、回调和变量；不能只改标题而留下陌生人员、活动按钮或空链接。模板不是固定配色和字段清单，也不为未接通的业务提供现成动作。

## 默认好看的判断标准

- 一张卡片聚焦一个结论或处理对象。标题说明对象，一句话摘要说明状态或变化；周期、来源等元信息降低字号和对比度，不挤占主信息。
- 默认优先原生卡片头部、语义颜色、字体和区块间距。主要颜色服务于主操作和信息强调；成功/风险颜色服务于业务状态。避免给每个字段都加背景、边框、图标或加粗。
- 指标按用户判断所需选择少量关键值，名称短、数值突出、单位明确；适合时使用指标卡/循环指标卡。长名称、长数值或大量指标应换布局或收起详情，不能强塞三列。
- 循环列表是简短摘要，标题、辅助说明与状态各有层级。长列表提供合理的查看完整内容入口；是否截取、截取多少按业务决定并说明，不能为漂亮丢失必需事项。
- 详情较长时使用折叠面板；默认可见区域仍应足以理解结论。通常突出一个主操作，其余动作降低强调；没有合法目标和实现的动作不放成可用按钮。
- 图片用于业务封面、内容或必要识别，按真实用途选择单图、多图或轮播，检查比例、裁切、加载和深色效果；不为增加组件种类强塞视频、头像或装饰图。
- 原生预览完成后检查手机窄宽、桌面、浅色/深色：标题和数值不截断、颜色可读、状态不靠颜色单独表达、主操作易找。仅 DOM 有文字不证明视觉通过，节点多也不证明设计完成。

## 可复用的项目简报样例

```bash
openyida sample yida-cool-card project-brief --var APP_URL=https://你的租户/真实应用ID --output .cache/cool-card/project-brief.json
```

这是本地导入文件生成，不会新建、保存或发送在线卡片。先改成当前业务的标题、周期、指标和明细，替换 APP_URL 并核对 JSON 格式，再在目标官方编辑器导入。变量和演示 Mock 位于 `JSON.parse(editorData)` 中；示例保留必要的原生完整属性及富文本辅助变量，不能仅因字段为空就删除。选择其他官方模板时按同一设计原则适配，不强制所有业务套用项目简报。

样例包括原生头部、富文本、循环指标卡、状态标签、进度条、循环明细、分割线、折叠面板和单一主操作。已核验官方编辑器保存、宜搭回读和重新打开；这不证明自动接入了业务数据或支持 CLI 保存。表达式、本地变量、表格和回调按需使用，示例没有实现它们，不能据此宣称全部类型都通过测试。

## 原生组件选型

| 信息或动作 | 优先考虑 | 注意 |
| --- | --- | --- |
| 标题/品牌/来源 | 卡片头部 | 不用连续粗体基础文本模拟所有层级 |
| 一句话摘要/复杂图文 | 基础文本 / 富文本区块 | 富文本包含编辑表示和 Markdown 数据绑定，不能只拼显示字符串 |
| 关键指标 | 指标卡 / 循环指标卡 | 和 Youshu 报表不是同一资源；以当前宜搭场景可用组件为准 |
| 状态/优先级 | 标签、公告栏 | 标签短而明确；告警有对应事实，不拿普通信息全部标红 |
| 人员/协作 | 用户信息变量、头像/人员列表 | 展示名字符串不等于 @ 人；实际映射由发送节点提供 |
| 多项摘要 | 循环容器、双列文本 | 循环变量类型匹配，预览多条不同数据及空数组 |
| 长说明/次级详情 | 折叠面板、分割线 | 默认收起不隐藏关键决策信息 |
| 明细数据 | 表格 | 使用表格专用协议，不把任意对象数组直接塞进去 |
| 跳转/办理 | 链接、按钮、聚合菜单 | 区分打开链接、回调业务与本地状态；保存不证明动作已执行 |

这是一组选型建议，不是组件白名单。编辑器的“基础组件”和“区块组件”都可以利用，区块可能由多个原生节点组合而成；从当前模板/编辑器读取真实配置，不凭名称猜 Schema。钉钉通用文档中的新组件也不自动证明当前宜搭场景支持。

## 变量、Mock 与交互

原生互动卡片实例由模板与数据组成。普通变量与发送时的 `cardData` 对应：文本、数字、布尔、数组/对象及用户信息、Markdown、表格等专用类型必须按目标组件契约匹配。公共数据对接收者可见；私有变量优先取对应的私有数据，不能把隐私字段混入公共 Mock。表达式变量用于组合计算，本地变量用于客户端临时状态；本地状态变化不等于服务端业务已保存。

为每个实际使用的变量说明名称、类型、来源、是否必填/可为空。Mock 是预览样例，不能充当真实数据接入；至少覆盖长标题、长数值、不同状态和空列表中与场景相关的情况。富文本组件的隐藏 Markdown 辅助变量属于编辑器协议，不要当垃圾字段删除。

动作依据[官方交互方式](https://open.dingtalk.com/document/isvapp/interactive-mode)选择：链接必须非空且目标正确；回传请求需有真实业务回调与上下文参数，成功提示的判定条件也需配置；确认框和动作面板只负责交互，不会自动实现业务；本地变量用于暂存时仍需实际提交链路。不能把“打开应用”按钮描述成“完成审批”，也不能用静态样例伪装交互成功。

## 交付与证据

可生成本地导入文件，交给用户在官方编辑器“更多 → 导入”，预览并点击保存；导入文件不携带 templateId、组织标识或编译产物，目标由当前编辑器决定。研究/验收时允许按已授权范围在专用测试卡片导入，但不能宣称 CLI 已保存模板。

富文本应同时核对可编辑内容、模板表达式和 Mock 的 Markdown 值；文字优先使用平台可适配的默认颜色，不能只改浅色颜色字段。明暗切换后还要检查实际文字颜色，必要时重新打开排除预览缓存。原生属性不能仅因值为空就裁剪，模板里存在不等于其每种编辑表示都已验证。

先看到导入内容生效，再显式保存；之后 CLI 回读同一资源，核对变量、节点和构建状态，并重新打开预览。兼容转换日志只作诊断线索，不能据一条 Durbo 告警断言组件不可用；以明确的保存结果和回读内容共同判断。回读仍是旧配置时，不能只凭当前画布或自动保存提示交付。保存、真实数据映射、客户端显示、回调执行分别报告。
