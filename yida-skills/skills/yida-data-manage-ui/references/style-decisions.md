# 调整维度与取舍

先从任务与当前页面找问题，再选择维度。以下是可自由组合的方法，不是固定皮肤、样式枚举或必须完成的清单。保留已经合适的部分；组合后检验主次关系，而非追求装饰数量。

| 可变维度 | 可以怎么变化 | 选择依据与边界 |
| --- | --- | --- |
| 表格线条 | 横线、网格、弱线、无内线、分组边界、隔行底色 | 对照密集数据需要定位；阅读列表可弱化竖线。不要为横线统一清空所有 div 的边框 |
| 容器关系 | 融入画布、轻边框、留白分区、轻投影、局部强调 | 先分清页面/操作区/表格的层级，避免每层都套卡片 |
| 页签 | 短下划线、文字强调、分段底色、紧凑选中块 | 看任务数量和当前层级；两个页签不必包全宽空框；保留选中与键盘焦点 |
| 操作区 | 主次按钮、左业务右工具、批量区、独立或一体工具带 | 主按钮对应真实高频操作，避免新增/导入/导出都同样抢眼 |
| 表头 | 弱底、强调底、深色、字重与分隔线 | 与正文形成恰当层级；固定占位表头、内部标签和排序图标都要覆盖 |
| 信息层级 | 关键列底色/字重、次要信息弱化、数值对齐 | 一到两处焦点即可；不把纯文字伪装成链接，不改变字段数据格式 |
| 配色与状态 | 从应用色派生表面、文字、边线和交互状态 | 颜色不是预置色板选择题；深色也需要可读禁用态、选中态和浮层 |
| 密度与节奏 | 工具区间距、容器留白、内层文本层级 | 原生虚拟行高只能由已验证的平台配置调整，不用 CSS 强改几何 |
| 固定区与滚动 | 固定列边界、滚动区底色、表头连续性 | 保留组件已有 sticky/transform/宽高计算，不破坏横滚与操作可达性 |
| 自定义页结构 | 表格、卡片、队列分栏、分组/时间视图、摘要与列表组合 | 由用户任务和数据规模决定，配色独立选择；不自动迁移原生页 |

## 将诉求变成修改说明

例如“数据管理重在操作”：先查看权限允许哪些高频动作、选中后有哪些批量动作，再加强主按钮对比和次操作分组，给筛选/排序保留稳定位置。不需要因此换表头、创建 KPI 或新增操作接口。

例如“只突出客户名称”：只处理真实名称字段的表头、底色与字重，以及 hover/selected；保留其他列和现有主题，不要求选择玫瑰或其他配方。

例如“视觉差异更大”：从当前基线推导组合，如弱化网格、用页签组织状态、让工具带融入容器、强调关键列。还可以使用完全不同的组合；不要机械套上述例子，也不要把差异等同于随机换色。

## 选择实现层

1. **平台已有 token**：有真实消费点时优先覆盖，保持既有主题继承。
2. **局部 CSS**：token 无法表达方向（如只去竖线、单列表头）时，用稳定容器和语义属性实现。
3. **自定义页组件**：只有已授权的自定义承载才调整布局与组件，保留事件、数据、权限和查询契约。

具体 token 与状态选择器见 [实施映射](token-and-css.md)。`list/generate` 是可选配方工具，不定义本技能的能力上限，也不是自由设计的前置步骤。
