# 样式选择与操作层级

机器可读的唯一目录：`openyida data-manage-style list --json`。24 种原生配方按六类组织：

| 维度 | style ID | 适合的诉求 |
| --- | --- | --- |
| 线条 | grid、horizontal、borderless、zebra | 网格核对、轻横线、无边界阅读、隔行扫描 |
| 容器 | flat、outline、shadow、double | 融入画布、明确边界、柔和面板、双线档案 |
| 操作栏 | integrated、toolbar-card、toolbar-tint、toolbar-dark | 一体操作、独立工具区、浅色分组、深色操作带 |
| 表头 | plain-header、tint-header、dark-header、reading | 简单表头、品牌强调、深色表头、阅读优先 |
| 配色 | paper、sage、ice、rose | 纸色、鼠尾草、冰蓝、玫瑰灰 |
| 深色 | dark-grid、dark-horizontal、dark-zebra、dark-flat | 深色网格、横线、斑马、无框 |

配方描述“阅读型”不意味着可以改变虚拟行高；默认保留原生密度。平台支持的密度配置可在独立授权和实际验证后调整，不能用 CSS 覆盖计算布局。

## 操作优先

`--focus actions` 在当前风格上增加工具带层次，提高主操作字重和点击面积，强调现有详情链接。不新增 KPI 或把业务处理页面改为展示看板。筛选、显示列、排序、刷新等次操作继续可达；不能把所有按钮都涂成主色，也不能用文字替换图标时丢掉事件绑定。

如用户特别强调批量操作，先检查选中记录后原生支持的动作，再优化其可见性；CSS 不创造平台不存在的批量接口。按权限禁用的按钮不能被强制启用。删除仍用危险色，不能突出为主要工作路径。

## 已验证的易错点

- 表头容器的 `color` 不会覆盖内部标签使用的 `--color-text1-4/10`，局部改表头 token，不能全页白字。
- 选择列表头内层已有底线，外层再加线会形成短双线。
- 使用表格真实字段属性定位，不能把固定列/表头容器的行高、top 和 transform 当作装饰属性修改。
- 深色页要覆盖原生 manager 与 content 的实际白底，不只设置 body token。
- “全部数据/表单提交”只有两个入口时不要用全宽空盒包住；同一操作组不同时套胶囊边框、阴影和大圆角按钮。
- 同一布局至少对比页签、左右工具、表头、行分隔、分页和浮层；差异性不等于随机换色。
- `--follow-shell` 是应用层 CSS 的按页规则；Canvas 不能上探父节点、注入 body 或重复更新应用配置。
