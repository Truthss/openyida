# 自定义页面响应式布局

设计、Canvas、历史 JSX 和已有页面美化共用本规则。响应式先保证内容与操作在当前容器中可用；等高只用于宽屏下需要成组展示的面板，不要求所有区块一样高。保留项目主题和密度，规则适用于门户、工作台、列表、详情以及抽屉中的自定义内容。

## 先确定可用宽度和重排方式

在已有 `design.md` 的布局、响应式和验收段落写清：哪些区域并排、何时换行或堆叠、堆叠后的顺序、表格如何滚动、哪些面板需要等高。不新增一份设计文件，不用“支持移动端”代替具体行为。

- 按内容容器的实际宽度设计，考虑平台侧栏展开/收起、拖拽调宽、抽屉和 iframe；不能只按设备名或屏幕宽度判断。宽屏中的窄抽屉也可能需要单列。
- 根据控件最小可用宽度、文字长度、列间距和主内容阅读宽度决定重排点。复用已有项目断点；断点未定义时按实际内容确定并记录，不把固定的手机/平板分界当作所有页面的标准。
- 优先用 Grid/Flex 的自动换行和可收缩列解决布局；子项设 `min-width: 0`，需要弹性宽度的网格列使用 `minmax(0, 1fr)`。仍需分级变化时，在运行环境支持的前提下使用容器查询；使用媒体查询时额外核验窄抽屉等容器场景。
- 重排保持业务阅读顺序、DOM 顺序和键盘焦点顺序一致，不用 CSS `order` 制造视觉顺序与操作顺序相反的布局。不因宽度变化隐藏原有字段、操作或模块。

## 筛选栏和组合控件

| 可用空间 | 布局规则 |
| --- | --- |
| 足够并排 | 标签和控件分层排列；同一行控件外框上下边缘对齐，按钮与输入控件底边对齐 |
| 一行放不下 | 字段组自然换行，操作区跟随换行；保留字段最小可用宽度，按钮文案完整可见 |
| 窄容器 | 字段按顺序纵向排列并撑满可用宽度；查询、清空等操作按可用空间并排或换行，不挤出容器 |

- 同组 Input、Select、日期控件和 Button 使用一致的组件尺寸与主题高度；统一标签字号、行高和标签到控件的间距。`Input.Search` 等组合控件同时检查外层、内部输入框、附加按钮和图标，不能只改外层高度。
- 标签、控件、帮助/错误信息分别占自己的布局位置。同排字段可共享标签行和控件行；长标签换行时由布局容纳最高标签，按钮仍按控件行定位，不能用各字段整个盒子的底边对齐导致错误信息把输入框顶歪。
- 无标签的操作区按控件行定位，不插入可读的假标签、连续空格或固定 `margin-top` 凑齐。帮助/错误信息在控件下自然增长，不覆盖下一行。
- 单行控件按主题高度保持一致；多行输入、长标签和反馈内容允许增长。不能为等高裁切文字，也不能缩小字体或压缩点击区域来维持一行。
- CSS 仅作用于当前页面或组件作用域；组件库内部结构使用当前版本支持的配置/样式入口，不能用全局 input/button 选择器改变原生表单。

## 主辅面板与分页

- 宽屏下，同一排且需要形成整体的主辅面板采用 Grid/Flex 拉伸外框；卡片内部纵向排列，主体可伸展，分页/底部操作用剩余空间置底。表格行和列表项保持自然高度，不跟着面板平均拉长。
- 不写死面板像素高度，不用脚本测量另一张卡片再复制高度，不用空占位、假数据或巨大外边距补齐。不相关区块、连续文章和瀑布流不强制等高。
- 宽度不足时主辅面板转为上下排列；按已确定的任务顺序展示，清除用于桌面等高的固定高度、最小高度和空白占位。单列时各面板由实际内容决定高度，分页接在内容之后。
- 内容差异过大时调整列宽、分组或堆叠时机，不能为了底边对齐留下整块空白。布局改变不允许增减记录、修改 `pageSize`、排序、筛选或分页状态。
- 未设计独立滚动的卡片不增加内部滚动条；工作区本来有受限高度时，按 [页面与导航连续性](page-continuity.md) 保持完整可收缩高度链和单一主滚动区域。

## 内容增长、表格与浮层

- 长标题、帮助文字和错误信息自然换行；无空格的长编号或链接设置合适的断行策略。只在已有明确设计允许时省略文字，并保留完整内容的访问方式。
- 宽表格保留列、数据和操作，通过表格自己的容器横向滚动；父级可收缩，不把整个页面撑宽，不用页面级 `overflow: hidden` 掩盖溢出。键盘操作、固定列和行内按钮仍应可达。
- 空数据、加载、错误和正常内容使用同一外部布局；空态保留必要上下文并按内容收敛，不保留为多条数据写死的高度。加载只替换内容，不重建查询状态。
- 抽屉和弹窗中的自定义内容也按自身宽度重排。检查下拉面板、日期面板和提示是否被裁切；不通过修改平台父容器或跨 iframe 注入样式解决局部布局问题。
- 优先保留同一组件树做 CSS 重排，不因断点切换组件 `key` 或重新挂载业务区域；筛选、页码、选中项、未提交内容和焦点不得因此丢失，也不能触发额外请求。

## 复用模板与 CLI 诊断

Canvas 页面需要同时覆盖平台侧栏、抽屉和 iframe 时，先复制容器响应式模板，再把现有业务区块和状态合入，不重建业务组件树：

```bash
openyida sample openyida-page-template canvas-responsive-layout --output .cache/samples/canvas-responsive-layout.jsx
```

模板提供带清理和帧合并的 `useContainerLayout`、命名容器查询、筛选栏、主辅面板、图表宽度通知和宽表局部滚动。断点是模板示例值，必须按当前内容最小可用宽度调整。图表收到容器宽度变化后调用自身 `resize`，不要读取一次 `window.innerWidth` 后固定尺寸。

`openyida compile <页面.canvas.jsx> --json` 与普通页面的 `check-page` 会给出以下非阻断诊断：只按视口宽度重排、`ResizeObserver` 未清理、480px 以上固定宽度、整页 `scale/zoom`。诊断有意保持为 warning，因为视口级抽屉和固定画布可能合理；仅在核实语义后使用消息中给出的 `openyida-responsive-*-ok` 标记，不用标记掩盖普通业务布局问题。

## 实际页面验收

按本页实际布局检查以下组合，记录容器宽度和结果；不以截图尺寸或编译通过代替运行态证据：

1. 宽屏、每个重排点前后及目标最窄容器；同时测试平台侧栏展开/收起和实际抽屉调宽。缩窄后再放宽，布局能恢复，无页面整体横向溢出。
2. 短/长标签、长标题和帮助/错误信息：标签与控件层次清楚，同排控件边缘一致，搜索组合按钮等高，操作无裁切或遮挡。
3. 主辅面板内容一多一少：宽屏需要等高的外框共边，分页位置合理；单列无多余高度，行高不被拉伸，不靠假内容填空。
4. 正常多条、单条、空数据、加载和失败状态；宽表格只在自身容器横向滚动，完整字段与操作仍可达。
5. 键盘遍历、放大文字或浏览器缩放后，内容与操作仍可用；调整宽度前后的筛选、分页、选择和草稿保持，原事件、请求参数及触发次数不变。
6. 至少记录 360、600、768、1024、1280、1600px 及实际重排点前后；这些宽度是覆盖矩阵，不是统一断点。桌面宽视口中另测同样宽度的侧栏、抽屉或 iframe，确认结果由内容容器而非浏览器宽度决定。

已有页面按 UI 美化流程先展示宽窄两种效果及必要的换行状态，经确认、备份后实施。只检查过源码或示意图时标记“响应式待运行态验证”；用本地样例或只读方式准备状态，不提交真实业务数据来制造测试场景。
