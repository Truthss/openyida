# 全应用覆盖与一致性

## 范围与清单

用户要求“美化应用”“配色统一和谐”“统一整个应用 UI”时，设计单位是该应用全部业务页面和浮层。先通过应用页面清单、导航配置、已有 PRD、页面 Schema/源码以及真实页面入口交叉核对；仅查导航菜单会漏掉隐藏入口、独立门户和抽屉内页面。缺权限或无法识别的页面记为待核实，不能当作不存在。用户明确只改某页时保留单页范围。

在本轮 `manifest.json` 的 `coverage` 中逐项记录资源 ID/入口、类型、父页面及承载方式、当前主题来源、新旧主题兼容证据、拟修改项、实现路径、备份引用和验收证据。浮层用父页面 ID + 触发动作定位，不伪造 formUuid。相同页面以整页、抽屉和 iframe 打开时，资源可以共享，但访问方式分别记录。

区分三个集合：全部需要达到一致效果的区域、需要实际写入的资源、已经验证的区域。已经协调的页面可保持原样但仍需检查；共用主题间接影响的页面不能漏出验收清单，也不必为这些页面制造单独写入。

| 区域 | 需要覆盖的内容 | 不能顺手改变的业务 |
| --- | --- | --- |
| 应用框架和导航 | 品牌、画布、菜单、分组、搜索、选中/悬停/焦点 | 菜单结构、可见权限、页面目标、导航模式 |
| 门户和首页 | 原生门户或自定义门户、已有模块、内容面、入口、移动布局 | 模块数据来源、链接、展示条件与访问权限 |
| 自定义页面 | Canvas 和历史 JSX 的工作台、列表、看板、详情等全部实际页面；可替换 UI 组件和展示结构 | 业务函数、事件语义、查询、业务状态管理、数据绑定与运行时；替换组件需核验等价绑定 |
| 原生表单 | 新增/编辑表单、流程表单、字段标签、分区、控件及反馈 | 字段定义、必填、校验、联动、提交和审批 |
| 表单详情 | 只读字段、附件、明细、流程状态、操作区 | 字段值、业务状态、按钮动作及权限 |
| 数据管理 | 原生列表、筛选区、表格、分页及状态表达 | 筛选/排序/分页行为、字段映射、数据权限 |
| 报表 | 原生报表、自定义图表、图例、坐标轴、提示、筛选与表格 | 查询条件、聚合、指标口径、系列绑定、联动及钻取 |
| 抽屉和其他浮层 | 抽屉、弹窗、下拉、日期选择、提示；外壳与内部表单/详情/页面分别检查 | 打开/关闭方式、URL、表单提交、回调和未保存处理 |

同一业务状态的颜色含义保持一致；报表分类色可使用协调的独立色板，不将所有系列强制改成品牌色。统一的是配色角色、文字层级、控件状态、边界、圆角和间距语言，不要求表单、报表、门户采用相同布局或密度。

## 主题能力和作用域

先核实服务端主题能力，只有 `appThemeEnable=y` 且 `appThemeMode=modern` 才按新版能力规划；老主题或未知能力按旧主题规则检查，不凭模板名称、应用创建时间或存储值推断。

应用主题保持一个设计源和一份应用级 CSS。自定义页只消费现有 token；原生组件使用实际支持的变量；图表、门户及第三方控件是否跟随需逐项核实。变量定义成功不表示所有消费方已接入。固定颜色、局部 CSS、组件 theme 配置需按获批范围适配，不能以业务重构解决样式问题。

抽屉外壳和内容可能在不同文档或主题上下文中：检查 Portal 挂载位置、Provider 范围、iframe 内实际主题及背景/文字。`iframePropagation` 的取值本身不是兼容证据。不得在页面中向 parent/top 注入整套主题、复制应用 CSS 到每个页面，或用全局通配选择器强行统一。跨域/平台不支持的区域如实列为受限，不能承诺全覆盖。

原生门户、原生报表只使用已核实且可恢复的主题/样式配置能力，不调用创建流程重建资源；缺少样式更新或恢复能力时，方案说明限制。自定义门户/报表沿用其原页面运行时，只改视觉属性。

## 方案、确认与验收

`visual-plan.html` 展示完整页面/区域清单，并为每种实际存在的页面类型及抽屉提供效果对照或明确标注的示意；相同视觉模式可合并展示但列出全部适用页面。清单标识“已协调，保持原样 / 跟随应用主题 / 单独适配 / 受限或待核实”，用户可以看清完整范围和未解决项。

面向用户可这样说明：“这次会统一应用中的门户、业务页面、填写表单、记录详情、报表，以及打开它们的抽屉和弹窗。配色、文字和控件风格协调，现有功能与数据保持原样。方案中列出了需要单独处理及暂时受限的位置。”根据实际清单措辞，不列不存在的页面，不隐去限制。

`ask_human` 的当前 revision 同时绑定视觉方案、覆盖清单和已知限制。发现漏页、新增适配或原以为自动继承的区域不支持时，先更新方案并重新确认受影响范围，不能静默省略。

验收覆盖每个实际页面和已有浮层入口，并按实际支持情况检查桌面/移动端、正常/选中/禁用/空/加载/错误状态；可用本地预览或无业务写入方式验证，不能为制造状态写业务数据。逐项记录“已验证 / 待验证 / 受限”及证据，不能以抽查替代全部页面已统一的结论。

用户接受有限范围时记录具体例外，交付描述同样写清；接受方案不等于证明受限区域已实现。恢复时恢复实际改动的共用主题和各资源，再复核同一份覆盖清单，包括只被主题间接影响的页面与浮层。
