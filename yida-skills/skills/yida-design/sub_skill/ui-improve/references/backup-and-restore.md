# UI 美化备份和恢复

应用主题使用 `app-theme snapshot/restore` 保存和恢复受支持的配置；页面使用各自已核实的恢复路径。没有通用整应用恢复命令，不能把导出迁移包、Git 分支或一张截图当成线上恢复能力。无法确认恢复路径时，停止该项修改并说明限制。

## 写入前的备份

在本轮 `ui-improve/<runId>/backup/` 中保存原始文件；目录不可复用或覆盖。`manifest.json` 记录相对路径、SHA-256、是否原本存在、资源环境/组织/应用/页面 ID、版本或内容指纹、采集时间、恢复命令及验证方式。备份不含登录凭据，不作为普通用户交付附件。

| 对象 | 必须保存 | 恢复准备 |
| --- | --- | --- |
| 本地文件 | 有效 `design.md`、页面源码及关联依赖、CSS、主题生成的 token 状态 sidecar、本轮会覆盖的其他派生产物 | 字节级副本；不存在的文件记录 `existed=false`，恢复时仅删除本轮新增且未被他人改动的文件 |
| 自定义页面 | 线上完整 Schema、解包后的可维护源码、依赖、页面数据源、动作/生命周期、组件树和版本 | 证明该页面可由对应发布路径无损维护；本地源码与线上不一致时分别保存，线上恢复使用线上源码 |
| 应用主题 | 经核实的现网主题配置快照、原主题 CSS 实体、品牌/导航配置、`customThemeStyle` 的 URL/文件名/启用与传播状态 | 为本次会改的键准备受支持的逆操作；核实所有联带改变能恢复 |
| 原生表单 | 完整 Schema、目标视觉属性的路径、原值及存在性 | 按受控 patch 契约生成正向/逆向补丁；只有能恢复原值（含属性原先不存在）时才允许修改 |
| 门户、报表和数据管理 | 本轮要改的原样式配置、完整承载配置/源码、主题依赖及原访问入口 | 自定义实现沿用原页面恢复路径；原生资源仅走已核实的样式逆操作，不重建资源，不改查询、聚合、权限和模块业务配置 |
| 抽屉及其他浮层 | 所属页面源码/样式、外壳主题来源、内部页面与 iframe 的主题依赖 | 外壳与内容分别纳入恢复依赖；共享资源只备份一次，保存全部受影响入口以便验证 |

应用级任务的备份和操作日志关联 [全应用覆盖清单](application-coverage.md)。只读保留其他受主题间接影响区域的原始证据，恢复共用主题后复核其外观；不能漏掉报表、门户或抽屉，也不能为回滚主题整份覆盖未直接修改的页面。

使用 `openyida get-schema <appType> <formUuid>` 获取完整页面 Schema；当前 CLI 会解析代码 bundle。不能拿 `--compact`、`--field-map-json` 或 `--analysis-json` 代替完整备份。按 `yida-get-schema` 的文件保存约定保存完整 JSON，内容被工具截断时不算备份成功；批量可用 `get-schema <appType> --all --summary-json --output-dir <本轮新目录>`，检查返回的每个 `schemaFile`，只将确认范围内资源纳入变更集合。

批量 `--summary-json` 保存的 Schema 不会展开代码 bundle；需要修改源码的页面再按单页完整命令读取并保存解包后的源码及依赖。不能把 bundle 引用当作已经备份的可维护源码。

Canvas 源码从实际 `YidaCodeCanvas.props.code` 读取，历史页面从实际动作模块源码读取；源码缺失、bundle 解析失败、依赖不齐或多个组件无法用现有发布命令保留时，停止源码美化。`publish` 不是通用完整 Schema 恢复：它会重新构建页面，即便保留 dataSource 也不能证明保留了全部组件、动作或页面配置。先比较原 Schema 与该发布路径的结构及非 UI 行为；不兼容时不能以重新发布单组件代替恢复。

### 应用主题快照与恢复命令

写入前保存现网主题配置和原 CSS 实体（每次使用新目录）：

```bash
openyida app-theme snapshot APP_XXX --output-dir <本轮目录>/before --json
```

命令核对环境、组织和应用，保存 `snapshot.json`、原 `theme.css` 及摘要，并返回 `restorableKeys`、`cannotClearKeys` 和受保护字段。既有 CSS 即使禁用也备份；仅记录 URL 不算完成。CSS 需直接返回 HTTPS `text/css`，下载失败、超限或采集期间配置变化都不能标记备份成功。快照只含应用主题配置，不代替页面 Schema、源码、依赖或业务配置备份。

**出方案前检查恢复能力**：平台逐键接口不能清空或删除配置，`cannotClearKeys` 中的键不能在本轮新增或修改。应用图标和主题模式只读保护、不支持恢复；`update-app --theme-file/--theme-color` 可能联带改变系统图标颜色，必须先核实且排除这种无法恢复的变更。不能以“先改了再试恢复”代替预检，也不能整包保存应用来绕过限制。缺少能力时缩小方案到可恢复的页面样式或已有配置，并明确说明。

每次成功写入并核验后，立即用同一快照命令保存到本轮新的 `after-N` 目录，记入操作日志；不能到用户要求恢复时才采集一份未知来源的当前配置作为修改后基线。恢复前先检查：

```bash
openyida app-theme restore APP_XXX --snapshot <本轮目录>/before/snapshot.json --expected-current <本轮目录>/after-N/snapshot.json --check --json
```

默认不写入，返回 `canRestore`、待恢复键和 `blockers`。确认本轮恢复已获用户授权且检查通过后执行：

```bash
openyida app-theme restore APP_XXX --snapshot <本轮目录>/before/snapshot.json --expected-current <本轮目录>/after-N/snapshot.json --confirm --output-dir <本轮目录>/restore-1 --json
```

`--confirm` 记录已有恢复授权，不能代替用户回答，也不要求重复确认。命令逐键恢复本轮实际改变的受支持主题项，保留原 CSS URL、文件名、启用和 iframe 传播状态；不重新上传、不改图标、不升级主题、不写业务配置。旧 URL 失效或内容与备份不同则停止，不能静默替换成新 URL。备份仍保留供后续人工处理。

每次写前检查当前主题是否仍匹配本轮基线，写后读回，并保存 `restore.json`。平台无事务或版本比较写入，不能保证绝对排除并发；部分失败或结果未知时检查日志和现网，不能盲目重试。CLI 的 `verified=true` 仅证明所记录配置一致，不代表页面外观或业务验收通过。`app-list` 只用于定位应用，`update-app` 的内部读取不等于持久化快照。

原生表单 patch 前加载 `yida-create-form-page/references/advanced-form-modes.md`，使用真实支持的 `openyida create-form patch <appType> <formUuid> <patchFile>`。不要猜 JSON Patch 协议，不以 `create-form create`、导入迁移包或重建字段恢复。补丁触及业务属性、复杂组件树或无法删除新增属性时，改为可逆的样式范围并重新确认。

备份后逐文件重新读取并验证摘要；解析 JSON/CSS/源码，检查目标 ID 和所有资源都齐全。只生成了目录或文件名不能标记 `backed_up`。备份与实施之间发生外部修改时，保留旧备份，重新取证和评估方案；影响方案则重新确认。

## 恢复步骤

1. 停止新的美化写入，读取本轮操作日志，识别成功、失败及结果未知的资源。未知先读回，不能把网络错误当成未写入。
2. 核对目标环境、组织、应用和页面，以及当前状态是否仍匹配本轮修改后的指纹。若已被其他人修改，不整份覆盖；只恢复能够证明仍属于本轮的视觉差异。冲突部分保留备份，说明冲突并等待用户决定，不能悄悄覆盖其他业务工作。
3. 按依赖逆序恢复已改资源：自定义页使用保存的线上原源码和原依赖，执行对应编译与 `openyida publish <原源码> <appType> <formUuid> --health-check`（Canvas 带 `--canvas`）；原生表单执行已核实的逆向 patch；主题恢复使用写入前准备好的命令。只恢复实际已改变的资源，不批量覆盖整个应用。
4. 恢复本地原文件及其副本中记录的状态，按清单处理本轮新增文件；保留本轮日志、方案、失败现场和备份。线上原源码与原本本地源码不同，则线上和本地分别恢复各自基线。
5. 读回恢复结果，比较非 UI 业务契约、视觉属性和原内容。平台 revision、重新编译字节或新 CSS URL 不一定一致，仅能忽略明确列明的非语义差异；功能、主题状态和素材内容不能忽略。验证实际访问页面，不以“文件已复制”宣称线上恢复完成。
6. 所有资源恢复并核验成功记 `rolled_back`。部分失败或不可验证记 `rollback_failed`，报告受影响资源及下一步；不删除备份，不假称恢复成功。已接受或已回滚的备份也不自动清理，供用户后续指定恢复版本。
