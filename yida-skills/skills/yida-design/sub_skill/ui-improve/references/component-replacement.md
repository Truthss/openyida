# UI 组件可以换，业务逻辑不能改

UI-only 不等于只能修改 CSS。允许替换按钮、输入控件、选择器、表格、卡片、图表、弹窗/抽屉等展示组件，修改 JSX 展示树、样式和必要的展示依赖；不要求保留原 UI 组件。业务函数、数据请求、计算、规则和业务状态管理实现保持原样，不以“效果相同”为理由重写、抽取或优化业务逻辑。原生表单的业务字段组件不属于这里的可替换展示组件。

替换前在本轮记录 `componentReplacements`：原组件、新组件、视觉目的、原输入数据/受控值、事件处理函数及参数、禁用/可见条件、加载/错误状态和验证方式。把替换范围及预计效果写入视觉方案，确认后才实施。

| 可以改变 | 必须保持 |
| --- | --- |
| 按钮组件、图标、位置和视觉强调 | 原操作函数、记录 ID、权限/禁用判断、触发时机与次数，不新增提交或重复调用 |
| 输入框、选择器、日期控件的外观实现 | 值类型、空值、多选、日期/时区语义、校验、默认值及原查询/提交参数 |
| 表格、卡片、列表或图表的展示方式 | 原数据集、字段信息、指标口径、筛选/排序/分页/选择/钻取行为，不启用组件自带的不同业务默认值 |
| 抽屉、弹窗的 UI 组件和内部排版 | 原入口 URL、打开/关闭条件、确认/取消/提交回调、未保存处理、业务状态和表单内容 |

允许在展示边界添加最小组件适配，例如把新输入组件的 `onChange(value)` 转交原处理函数需要的参数形态；只做组件接口适配，调用原业务函数，保持参数语义、值类型及副作用时机/次数。不得改变业务函数体、补业务默认值、转换业务含义、添加查询或写请求。不能证明等价时保留原组件，用样式或包装完成视觉目标。

改变组件类型、key 或挂载层级可能导致卸载重建。必须保持已输入内容、筛选/分页/选中状态和原生命周期行为，不能因换组件重置业务状态、重复请求或丢失未提交数据。纯展示状态可按需适配，不能借此迁移业务状态管理或页面运行时。

发布前对比备份：业务实现应无改动；允许的 diff 限于展示结构、样式、展示依赖及有记录的最小组件适配。用相同输入检查原处理函数接收的参数、触发次数和关键状态；涉及写操作用本地 mock/spy 等无真实业务写入方式验证。编译通过、截图变好或按钮仍可点击，都不能代替业务契约核验。发现越界先撤销该变化，不能通过修改业务逻辑迁就新组件。
