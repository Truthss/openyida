# 流程与自动化通用节点配置

本技能统一说明节点配置，不负责创建资源或保存发布。流程由 `yida-process-rule` 处理，自动化由 `yida-integration` 处理；已由入口加载本技能时，配置完成后直接交回调用方，无需重复加载入口。

## 先选类别，只读需要的配置

每份参考按“什么时候用 → 必填配置 → 最小示例 → 特有限制”展开。只配置一个节点时，不读取其他类别。

| 类别 | 包含节点 | 读取说明 |
| --- | --- | --- |
| 发起 | 流程发起、自动化触发 | [发起](references/start.md)：流程的字段权限/发起范围，与自动化事件不同 |
| 人工处理 | 审批、办理、旧版多人审批、抄送 | [人工处理](references/human.md)：节点差异；选谁处理读 [人员](references/actors.md) |
| 流转控制 | 条件分支、并行、循环 | [流转控制](references/control.md)：明确流程与自动化的支持范围 |
| 数据操作 | 查询、新增、更新、删除，单条/批量 | [数据](references/data.md)：来源、筛选、赋值及两种格式 |
| 通知 | 消息、邮件、卡片 | [通知](references/notifications.md)：对象、正文和平台/CLI 边界 |
| 扩展执行 | 连接器、子流程、代码、AI | [扩展执行](references/extensions.md)：真实动作、输入和输出 |

## 相同配置只说明一次

| 配置项 | 何时读取 |
| --- | --- |
| [人员选择](references/actors.md) | 指定成员、角色、主管；审批/办理/抄送分别使用对应参数 |
| [字段权限](references/fields.md) | 可编辑、只读、隐藏及子表；发起用顶层 `startFormConfig`，人工节点用 `formConfig` |
| [操作按钮](references/actions.md) | 审批、办理、旧版多人审批的加签/转交；抄送和自动化不适用 |
| [条件与变量](references/conditions-variables.md) | 字段与固定值、字段与字段比较；触发条件、分支和取数各用对应格式 |
| [统一公式引导](../yida-formula/SKILL.md#写配置前先处理这些易错点) | 右侧选择公式、计算赋值或按公式进入分支时读取；先核对可引用的上游字段，再保留执行文本和编辑器内容 |

配置人工节点的处理人和字段权限时，只读人工处理、人员选择、字段权限。需要加签或外部动作时，再加载对应说明。

## 分清配置能力

- **可直接生成配置**：当前 CLI 有明确输入契约；真实资源 ID、字段、角色或连接器 schema 仍须先取得。
- **需要已有真实配置才能透传**：流程编译器接受该组件，但业务 props 需来自现有配置或已验证接口；不能只凭节点名称编造。
- **当前 CLI 未封装**：平台有、当前入口没有输入契约。明确报告缺口，不能换另一种节点或改变触发语义交付。
- 共用配置思路不等于同一 JSON。流程定义用原生组件字段或流程 DSL；自动化用 spec。各类别说明分别标明格式。
- 人员“指定角色”决定谁处理；“条件模式”在同一节点按条件选人；“条件分支”改变走向。数据隔离和多角色字段访问属于表单权限组，交给 `yida-form-permission`。

## 配置检查

引用权限矩阵前，执行 `openyida get-permission <appType> <formUuid> --check-matrix --json`，按 `matrixAvailability.usage.status` 判断能否继续；具体处理见 [矩阵配置](../yida-form-permission/references/row-field-access.md#引用已有矩阵)。

其他节点按对应配置 CLI 的返回结果处理。明确提示权益不足时，再按返回的权益名称或链接引导开通；查询失败或结果未知时先排查，不直接要求升级。

配置回读只证明配置已保存；实际审批、数据写入或通知送达需要运行证据。按 CLI 返回的验证等级报告结果。
